# Code of conduct

This is a small technical project. The rules are short because the standard is ordinary
professional conduct, not a procedure.

## What is expected

**Argue about the work, not the person.** Disagreement about a design, a measurement or a patch is
the point of the project. Contempt for the person holding the position is not, and it is the one
thing that reliably ends a technical discussion early.

**Bring evidence.** A claim about what the code does should come with a way to check it — a log, a
command, a commit. This matters more here than in most projects: acl is a compatibility layer whose
documents have already been wrong about its own capabilities, in both directions. Assertion is not
status.

**Assume competence and missing context, in that order.** Most of what looks like a bad decision in
this tree is a decision made against a constraint that was never written down. Ask what the
constraint was.

**Accept that scope is bounded.** A maintainer declining a feature, a platform or a dependency is
not a judgment about the person who asked. acl deliberately does not accept some contributions at
all — anything derived from the GPL-3.0 project that preceded it, for the reasons in
`PROVENANCE.md`.

## What is not acceptable

Harassment of any kind, including sustained personal hostility, deliberate intimidation, sexual
attention or imagery, and publishing someone's private information. Repeated attempts to litigate a
settled decision after it has been explained. Deliberately wasting other people's time, which
includes submitting work you have not read, generated or otherwise, and presenting it as your own
understanding.

Any of these can be grounds for having a comment removed, a pull request closed, or an account
blocked from the repository, with no requirement that it be the second offense.

## Scope

This applies in the repository — issues, pull requests, reviews, commit messages — and wherever
someone is representing the project elsewhere.

## Reporting

Email **joel.winarske@linux.com**, the address in every commit in this tree. Include links and
enough context to tell what happened. Reports are read by the maintainer and are not discussed
publicly.

If what you have found is a security vulnerability rather than conduct, it goes somewhere else:
`SECURITY.md`, through a private GitHub advisory.

## How this is enforced

By one maintainer, using judgment, with no committee and no appeals process. That is an honest
description of a project this size rather than an aspiration to something larger. If the project
grows past the point where one person's judgment is enough, this document gets rewritten rather
than quietly ignored.
